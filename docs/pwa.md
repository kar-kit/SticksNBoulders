# Install and the service worker

The logger has been durable since Order 9: a set goes to IndexedDB before it
goes anywhere else ([offline.md](offline.md)). What it could not do was
**open** with no signal. Kill the app in the gym basement, reopen it, and the
browser had nothing to show. This fixes that, and makes the app something you
install rather than bookmark.

## What is cached, and what never is

`public/sw.js` is short plain JavaScript on purpose. Read it; it takes five
minutes.

| Request | Strategy | Why |
| --- | --- | --- |
| Page navigations | Network first. After 2s, or on failure, the cached copy. No copy: `/offline` | Online always means current code. The cache only serves when the network does not. |
| `/_next/static/*` | Cache first | Hashed filenames. The content under a URL never changes. |
| `/manifest.webmanifest` | Network, cache on failure | |
| `/api/*` | **Never touched** | Authenticated with a per-user JWT. |
| Anything cross-origin | **Never touched** | That means all of Appwrite: sessions, rows, clips, permission decisions. |
| RSC payloads, images, everything else | Never touched | A failed RSC fetch makes Next fall back to a full navigation, which the worker then serves. |

On install it caches the athlete shell (`/`, `/today`, `/log`, `/history`,
`/me`, `/bodyweight`, `/sign-in`, `/offline`) and every chunk, stylesheet and
font those pages reference. It is all or nothing. If one page fails, the
install fails and the previous worker keeps serving.

### Why this cannot leak one account into another

Three rules, each enforced in the worker rather than by convention:

1. **Only responses the server marked shareable are stored.** Anything with
   `no-store` or `private` is refused. Every page that can differ between two
   people (`/history/[id]`, `/lift/[id]`, `/coach/athletes/[id]`) renders
   dynamically, and Next marks dynamic renders `no-store`. The static pages
   are byte-identical for every visitor. The signed-in user's data reaches
   them afterwards, straight from Appwrite, under that user's own session.
2. **Nothing authenticated goes through the worker.** Appwrite is cross-origin
   and `/api/*` is excluded, so no permission decision can be served stale.
   Revoke a coach link and the next read is refused by Appwrite, exactly as
   it would be without a worker.
3. **Pages are stored by path, never by full URL.** An OAuth callback or a
   password-reset secret in a query string never becomes a cache key.

`npm run e2e:pwa` signs a real athlete in, logs a set, and then asserts that
no cache holds an `/api/` URL, an Appwrite URL or a query string.

## Updates

- The worker is registered as `/sw.js?v=<build id>`. The build id is
  `SNB_BUILD_ID` if the host sets it, otherwise the git commit
  (`next.config.ts`). A new deploy is therefore a new worker, and when it
  activates it deletes the old caches.
- `/sw.js` is served `no-store` and registered with `updateViaCache: "none"`.
  A stale worker script is the classic way a deploy strands people on old code.
- The new worker calls `skipWaiting` and `clients.claim`, and takes over at
  once. **It never reloads the page.** An athlete mid-set keeps the page they
  have. Their next navigation gets the new code, because pages are network
  first and `deploymentId` makes Next hard-reload when a client's build does
  not match the server's.
- A home-screen app gets resumed much more often than it gets opened, and the
  browser only checks for a new worker on a navigation. So the page also calls
  `registration.update()` when it comes back to the foreground, at most once
  an hour.

**Kill switch.** If a bad worker ever ships, deploy a `public/sw.js` whose
`activate` deletes every `snb-` cache and calls
`self.registration.unregister()`. Browsers re-fetch the script on the next
navigation, so it spreads on its own.

## Install

- **Manifest** (`app/manifest.ts`): id, name, short name, standalone,
  start_url and scope `/`, and the app background `#1d1c22` as both
  background and theme colour. Icons come at 192 and 512, both plain and
  maskable. The mark sits inside the maskable safe zone.
- **iOS** (`app/layout.tsx`): apple-touch-icon (180), `apple-mobile-web-app-*`
  meta, `black-translucent` status bar over the safe-area padding the shells
  already have, a launch image per current iPhone screen (`lib/pwa/splash.ts`,
  generated by `scripts/pwa-splash.mts`), and phone-number detection turned off
  so loads are not turned into `tel:` links.
- **No white flash**: the `<html>` element carries the background colour
  inline, so the first frame is dark before any CSS arrives. Android's launch
  screen comes from the manifest colours and iOS's from the launch images.
- **Install hint** (`components/pwa/install-hint.tsx`, rules in
  `lib/pwa/install.ts`): a small card on Today. On Android and desktop Chromium
  it holds `beforeinstallprompt` and offers the browser's real prompt. On iOS
  it says "Tap Share, then Add to Home Screen". It never appears on the first
  day, inside an in-app browser (Instagram and similar cannot install), once
  installed, or for 60 days after "Not now". [Inference: those thresholds are
  my guess, not a requirement.]

## Verified here vs. needs HTTPS hosting

`localhost` counts as a secure context, so Chromium runs the worker exactly as
it would over HTTPS. Verified with `npm run e2e:pwa` against a production
build:

- The manifest parses, every declared icon has the size it claims, and the
  maskable icons are present.
- The apple-touch-icon, the iOS meta tags and all six launch images are linked
  and have the right dimensions.
- The worker registers, takes control without a reload, and caches the shell.
- With the **whole browser offline**, `/sign-in`, `/today` and `/log` open from
  the worker, and an uncached screen gets `/offline` rather than the browser's
  error page.
- A signed-in athlete, cold start, fully offline: the logger opens, a session
  starts, a set logs as queued, it survives the app being reopened, and it
  lands exactly once when the network returns.
- No API response, Appwrite response or query-string URL ends up in any cache.
- A new build's worker takes over without a reload and deletes the old caches.

These need a real HTTPS host and real phones:

- **Chrome's install prompt on the Galaxy S24 FE.** `beforeinstallprompt` only
  fires on a real origin that passes Chrome's installability checks. Check the
  card appears on day two, that Install opens the prompt, and that the
  installed app launches standalone with a dark splash.
- **iOS Add to Home Screen on the iPhone 15 Pro and iPhone 16.** Check the
  icon and the "SnB" label, that the launch image shows instead of white
  [Unverified on current iOS], that the status bar sits over the dark
  background with nothing clipped by the Dynamic Island, and that a cold
  launch in airplane mode opens Today and Log.
- **Real offline on a phone.** Airplane mode, and gym wifi that connects but
  routes nowhere (the 2s timeout path; the headless check can only simulate a
  hard disconnect).
- **An update on an installed app.** Deploy twice, resume the installed app
  after the second deploy, and confirm the next navigation runs the new build.
- **iOS storage eviction.** WebKit exempts home-screen apps from its 7-day
  storage cap, and that exemption is the main reason to install on iOS.
  Confirm the queue and the worker's caches survive a week without opening
  the app.
